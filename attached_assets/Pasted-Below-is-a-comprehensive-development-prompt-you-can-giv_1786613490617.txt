INNDOS Marketing & Marketer Referral Tracking Module — Development Prompt

Build a Marketing/Referral Management Module for the existing INNDOS platform at inndos.com.

The first version of this module must focus specifically on allowing the Admin to assign existing INNDOS users as Marketers, generate unique marketing/referral links or promo codes for them, track users who register through those links, and provide detailed analytics to both Admin and the respective Marketer.

Do not build advanced advertising, campaign management, email marketing, SMS marketing, social media automation, or paid advertising features at this stage. This module is primarily a referral/affiliate tracking and marketer performance monitoring system.

1. MARKETER ROLE MANAGEMENT
Admin: Convert User to Marketer

Add functionality to the Admin Dashboard that allows an administrator to:

Search for any existing INNDOS user.
View the user's basic profile information.
Convert the user from a normal user into a Marketer.
Assign a unique marketer identification/reference.
Activate or deactivate the marketer.
View when the user was converted into a marketer.
View the marketer's current status.

The system should NOT create a duplicate user account.

An existing INNDOS user should simply receive the additional Marketer role/permissions.

Example:

User
↓
Admin converts user
↓
User + Marketer Role
↓
Marketer Dashboard becomes available

The existing user's normal INNDOS functionality must remain unchanged.

3. UNIQUE MARKETING / REFERRAL LINK

When an Admin converts a user into a marketer, automatically generate a unique referral code and referral link.

Example:

https://inndos.com/register?ref=MKT00025

or

https://inndos.com/register?promo=MKT00025

The exact URL structure should follow the existing INNDOS routing architecture.

The system must be able to identify that:

New User → Registered through → Marketer X

The referral relationship must be stored permanently in the database.

4. REFERRAL TRACKING

When somebody visits a marketer's referral link:

The referral should only become a successful referral/registration once the person successfully creates an INNDOS account.

Do not count someone merely opening the referral link as a registered user.

6. PREVENT DUPLICATE REFERRAL COUNTING

A user must not be counted multiple times as a successful referral.

For example:

If Ahmed clicks John's referral link five times and eventually registers:

John's successful referrals = 1

NOT:

5

The system should associate the registration with the appropriate marketer only once.

Use the user's unique account/user ID as the primary basis for successful referral counting.

30. IMPORTANT BUSINESS RULES

Implement these rules carefully:

Every marketer must have a unique referral code.
Every marketer must have a unique referral URL.
One user account should only count once as a successful referral.
Historical referral relationships must never be deleted simply because a marketer becomes inactive.
Deactivating a marketer must not delete historical data.
A normal user can become a marketer without creating a second account.
A marketer can only see their own referral information.
Admin can see all referral information.
Referral statistics must be calculated from actual database records.
Registration date/time must be stored accurately.
Referral attribution must survive logout/login.
Referral codes must not be easily duplicated or guessed in a way that compromises the system.
Historical referral records must remain associated with the original marketer even if the referral code is later changed.
Do not expose authentication credentials or passwords through marketing analytics.
Existing INNDOS user functionality must not be broken by introducing the marketer role.

FINAL DEVELOPMENT INSTRUCTION

Build this as a production-ready Marketing/Referral Module for INNDOS, integrated into the existing platform.

The primary purpose of Version 1 is:

Admin assigns users as marketers → each marketer gets a unique referral/promo link → people register through that link → INNDOS records the marketer attribution → marketer sees their own referrals → Admin sees all marketers, referrals and complete analytics.

Keep the implementation clean, secure, scalable, responsive, and consistent with the existing INNDOS architecture and UI.

Do not introduce unnecessary marketing features in Version 1. Focus on making the marketer referral tracking, attribution, dashboard, administration and analytics reliable and accurate.
